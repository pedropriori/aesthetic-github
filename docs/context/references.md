# Referências úteis (catálogo)

Este documento cataloga referências que vamos usar para guiar decisões de **layout**, **métricas**, **assets** e **automações** do Profile Kit.

## Curadorias de perfis e templates

- **Awesome GitHub Profile README (curadoria grande)**  
  `https://github.com/abhisheknaiidu/awesome-github-profile-readme`  
  - Útil para: ver padrões recorrentes (minimal, descriptive, dynamic, etc.) e evitar “overdesign”.

- **Awesome Git Profile (guia por peças + templates)**  
  `https://github.com/flyingsquirrel0419/awesome-git-profile`  
  - Útil para: enxergar o perfil como composição de “blocos” (header, typing, stats, layout, actions).

## Métricas e cards (SVG)

- **lowlighter/metrics (infográfico altamente configurável)**  
  `https://github.com/lowlighter/metrics`  
  - Útil para: 1 SVG “premium” (quando bem configurado e com poucos plugins).
  - Setup via action (documentação):  
    `https://github.com/lowlighter/metrics/blob/master/.github/readme/partials/documentation/setup/action.md`

- **GitHub Readme Stats (cards clássicos)**  
  `https://github.com/anuraghazra/github-readme-stats`  
  - Útil para: 1–2 cards (stats + langs) com layout limpo e alinhado.

- **ghstats / ghstats-cards (gera assets local e commita no repo)**  
  `https://github.com/tiennm99/ghstats`  
  - Útil para: confiabilidade e “zero downtime” (assets no repo, sem depender de endpoint externo).

- **github-stats-cards (Python action/CLI de cards)**  
  `https://github.com/stn1slv/github-stats-cards`

## Kits “assets-first” (header/divider/footer + config única)

- **easy-github-profile (assets SVG + config única)**  
  `https://github.com/BerkaySevinc/easy-github-profile`  
  - Útil para: entender a abordagem “assets versionados + README simples”.

## Tipografia/efeitos (usar com moderação)

- **TypingSVG (typing animation mais flexível)**  
  `https://github.com/whiteSHADOW1234/TypingSVG`  
  - Útil para: 1–2 linhas no hero (se encaixar no blueprint), sem virar “carnaval”.

## Exemplos com foco em consultoria/oferta (estrutura de landing)

- **Seção “business” com pacotes e CTA no Profile README (exemplo forte)**  
  `https://github.com/Turbo31150/Turbo31150/commit/044d44e8b88efc93502d913df510fc2485cbbad7`  
  - Útil para: “oferta empacotada” (pacotes) + prova (números) + CTA.

- **Consulting README separado (serviço/escopo/disponibilidade)**  
  `https://github.com/oleg-nenashev/oleg-nenashev/blob/main/consulting/README.md`  
  - Útil para: linguagem de consultoria, escopo e disponibilidade.

## Nota sobre “commit art”

Existem ferramentas de “commit art/painter”, mas **não vamos seguir esse caminho** por dois motivos:
- conflita com o posicionamento premium/profissional (parece apelo)
- foge da premissa do projeto (sem “hack do gráfico”)
